\# CodeWisdom AI 全链路代码智能治理与多维度迭代平台（规范版）



> 说明：本文档为阶段性技术方案，非最终版本。涉及第三方 SDK、版本兼容、Java 生态支持情况的内容，均需先做技术验证，再进入正式开发。

\## 1. 项目概述



\### 1.1 项目背景



在软件开发、课程设计、开源项目维护、企业老旧项目迭代中，存量项目常见问题包括：



\- 缺少标准化文档

\- 代码注释缺失

\- 项目架构不清晰

\- 潜在 Bug 较多

\- 依赖版本混乱

\- 模块耦合严重



开发人员接手陌生项目时，往往需要人工遍历源码，手动梳理架构、排查隐患、补全文档、解决依赖冲突。该过程重复度高、效率低，且容易遗漏。



现有 AI 代码辅助工具存在以下局限：



\- 多为 Python 单脚本或轻量工具

\- 主要支持单文件分析，难以处理完整多模块工程

\- 缺少批量仓库拉取、全项目架构逆向、依赖全局校验能力

\- 缺少系统化评测机制，分析效果难以量化

\- 单体架构扩展性有限，难以支撑后续迭代与并发部署



因此，本项目计划构建一个工程化、可扩展、可部署的全链路代码分析平台，支持多源项目导入、架构逆向、缺陷审计、业务规则辅助还原、文档注释生成、修复建议、在线预览、打包导出和智能体评测。



\### 1.2 项目目标



系统支持通过以下方式导入项目：



\- GitHub/Gitee 公开仓库地址

\- 本地 ZIP 压缩包

\- 批量源码文件



核心目标包括：



\- 项目架构可视化逆向

\- 代码缺陷辅助审计

\- 依赖冲突检测

\- 隐性业务规则辅助还原

\- 代码注释与项目文档自动补全

\- 代码缺陷修复建议生成

\- 修改内容 Diff 对比

\- 轻量项目沙箱运行

\- 优化后项目打包下载

\- 智能体能力量化评测



项目采用“先本地开发调试，后线上部署”的迭代流程。本文档描述的是阶段性目标，后续根据实际运行反馈持续调整。



\### 1.3 技术栈选型



\#### 1.3.1 核心架构技术



\- 后端主体：Spring Boot 3.x

\- 微服务框架：Spring Cloud Alibaba，具体版本以官方兼容矩阵为准

\- 服务注册与配置：Nacos

\- 流量控制与熔断降级：Sentinel

\- 统一网关：Spring Cloud Gateway

\- 多智能体编排：LangGraph（Python/JS）或 LangGraph4j（待验证）

\- 评测体系：LangHarness 或自研评测模块（待验证）

\- 代码解析：Tree-Sitter，优先 Java 绑定；若部署复杂，可拆为独立解析服务



> 技术验证项：

> - LangGraph 是否有稳定可用的 Java SDK

> - LangHarness 是否有 Java SDK

> - Tree-Sitter Java 绑定的 native 依赖与部署复杂度

> - Spring Cloud Alibaba 与 Spring Boot 3.x 的兼容版本

>

> 若 Java 智能体生态不成熟，建议采用：

> \*\*Java 微服务负责业务 + Python 服务负责 LangGraph 智能体编排，通过 REST/MQ 通信。\*\*



\#### 1.3.2 数据存储与中间件



\- MySQL 8.0：用户操作记录、项目解析记录、审计记录、评测指标、文档生成记录

\- Redis 7.x：缓存项目架构数据、临时状态、智能体缓存结果

\- MinIO：存储上传压缩包、源码文件、生成文档、优化后项目包

\- RabbitMQ：异步处理大项目解析、批量文档生成、评测任务



\#### 1.3.3 辅助工具与前端



\- 仓库处理：JGit

\- 数据建模：MyBatis-Plus、Jackson、MapStruct

\- 前端：Vue3 + Element Plus

\- 构建与部署：Maven、Docker



> 删除说明：原文“Pydantic Java 适配模型”不合理。Pydantic 是 Python 生态库，Java 侧应使用 Jackson、MapStruct、MyBatis-Plus 等。



\#### 1.3.4 技术选型原则



\- 优先选择成熟、可维护、社区活跃的技术

\- 微服务拆分以业务边界为准，初期避免过度拆分

\- 中间件按实际场景引入，不做无意义堆叠

\- 智能体相关技术必须先验证，再决定集成方式

\- 保持 Java 主技术栈统一；若必须引入 Python 智能体服务，通过标准接口通信

\## 2. 功能性需求



\### 2.1 项目多源导入模块



支持三种导入方式：



1\. Git 仓库导入

&#x20;  - 输入公开 GitHub/Gitee 仓库地址

&#x20;  - JGit 拉取源码、识别分支、克隆项目

&#x20;  - 过滤 `.git`、`target`、`node\_modules`、缓存文件等无效资源



2\. ZIP 压缩包导入

&#x20;  - 上传 ZIP 项目压缩包

&#x20;  - 后端解压、遍历多级目录、构建标准化项目文件树

&#x20;  - 分类存储源码文件



3\. 批量源码文件导入

&#x20;  - 支持上传 Java/Python 等主流源码文件

&#x20;  - 用于单文件或小项目分析



\### 2.2 全项目架构逆向分析



\- 扫描项目多级目录，生成可视化树形文件结构

\- 基于 Tree-Sitter 解析包结构、模块分层、类定义、方法依赖、跨文件调用关系

\- 生成 Mermaid 架构图、模块调用关系图、依赖拓扑图

\- 识别技术栈、项目类型、架构风格、模块职责

\- 生成项目架构说明书，作为辅助文档，需人工校验



\### 2.3 代码缺陷与冲突审计



对项目代码和依赖进行辅助审计，定位文件与行号，并分级输出风险：



\- 常规代码问题：空指针、未捕获异常、参数校验缺失、硬编码、逻辑冗余、死代码、循环逻辑问题

\- 依赖冲突：解析 `pom.xml`、`requirements.txt` 等，检测版本冲突、重复依赖、无效依赖、兼容隐患

\- 架构隐患：模块循环依赖、过度耦合、分层混乱、职责不单一

\- 风险分级：高危/中危/低危，附带问题描述、文件与行号、风险说明、触发场景



\### 2.4 业务规则逆向分析（探索性功能）



针对无文档、无注释的老旧项目，辅助还原业务规则：



\- 提取核心业务流程、执行链路、分支判断逻辑

\- 识别业务约束、数据校验规则、状态流转、权限控制逻辑

\- 跨模块一致性校验，检测逻辑冲突与规则不一致

\- 输出结构化《项目业务规则说明书》，需人工确认



> 说明：业务规则逆向难度高，准确性有限，定位为辅助功能，不承诺完全自动还原。



\### 2.5 智能文档与注释自动生成（可自定义开关）



用户可自主开启或关闭：



\- 批量补全类注释、方法注释、参数注释、返回值注释、复杂代码块行注释

\- 生成标准化 README：项目介绍、技术栈、目录结构、启动方式、注意事项

\- 生成接口文档、模块说明、部署文档、依赖说明



\### 2.6 在线代码修复与高亮对比



\- 针对检测出的 Bug、不规范代码、依赖隐患，生成修复建议

\- 前端展示修改前后 Diff 高亮对比

\- 支持 HITL 人工介入：人工审核、手动修改、驳回重生成

\- 支持多轮迭代修复，直到用户确认



> 说明：默认不自动修改用户仓库，修复以建议和 Diff 形式呈现，由用户确认。



\### 2.7 项目运行与导出智能判断



系统识别项目依赖复杂度，分支处理：



\- 轻量项目：无 Redis、MySQL、MQ 等中间件依赖的简单项目，可在 Docker 隔离沙箱中运行预览

\- 重型项目：含多中间件、数据库依赖、复杂环境配置的项目，禁止网页沙箱运行，提供本地部署指引

\- 通用导出：支持一键打包 ZIP 下载完整项目源码



> 说明：沙箱运行必须隔离、限资源、默认不执行危险代码。当前判定规则为阶段性方案，后续持续优化。



\### 2.8 自动化评测功能



\- 内置标准化测试项目数据集，含人工标注标准答案

\- 覆盖常规项目、缺陷项目、冲突项目、无文档老旧项目

\- 支持批量执行解析、审计、修复任务

\- 量化指标：Bug 检出召回率、缺陷误报率、架构识别准确率、业务规则匹配率、文档注释质量评分

\- 错误溯源：定位仓库解析、代码解析、审计、修复、文档生成等节点误差

\- 生成可视化评测报告，支撑 Prompt 与规则迭代



> 说明：评测框架优先验证 LangHarness；若不可用，则自研轻量评测模块。

\## 3. 非功能性需求



\### 3.1 可用性



操作流程简洁，用户导入项目后可自动完成主要分析流程。本地开发阶段保证核心功能可用，上线后支持多用户并发。



\### 3.2 稳定性



\- 全局异常捕获：仓库拉取失败、文件损坏、解析异常、任务超时等给出友好提示

\- 微服务熔断降级：避免单节点故障导致整体系统崩溃



\### 3.3 可扩展性



\- 基于 Spring Cloud Alibaba 模块化拆分

\- 各服务解耦，可按需新增检测规则、适配语言、文档模板、评测指标



\### 3.4 可评测性



\- 全流程可量化、可复测、可溯源

\- 通过评测模块持续迭代智能体能力



\### 3.5 可部署性



\- 支持本地开发调试、测试环境联调、线上生产部署

\- Docker 容器化打包



\### 3.6 安全性



\- 默认不执行用户代码

\- 沙箱隔离运行，限制资源

\- 文件上传、仓库拉取做安全校验

\- 防止恶意文件注入

\## 4. 系统整体架构设计



\### 4.1 架构模式



采用 Spring Cloud Alibaba 微服务架构 + 多智能体编排工作流。支持服务独立开发、部署、迭代，并支持分支路由、循环迭代、HITL 人工介入。



\### 4.2 微服务模块拆分



目标架构可拆为：



\- 网关服务：统一入口、路由、跨域、限流、权限拦截

\- 项目资源服务：仓库拉取、文件上传解压、文件树构建、MinIO 管理

\- 代码解析服务：Tree-Sitter 结构化解析、架构提取、依赖分析

\- 智能审计服务：Bug 检测、依赖冲突校验、架构风险排查、风险分级

\- 业务逆向服务：业务规则提取、跨模块逻辑校验、流程还原

\- 文档生成服务：注释补全、文档生成、格式化

\- 代码修复服务：修复建议、Diff、多轮迭代

\- 运行导出服务：环境判定、沙箱预览、打包下载

\- 智能评测服务：指标计算、错误溯源、评测报告

\- 数据持久化服务：统一操作 MySQL、Redis，负责存储、缓存、查询统计



> MVP 建议：初期不要全部拆开。可先合并为：

> 1. gateway

> 2. project-resource

> 3. code-analysis（解析+架构+审计）

> 4. agent-orchestration（业务逆向+文档+修复+HITL）

> 5. evaluation-export（评测+运行导出+数据）

>

> 待流程稳定后再逐步拆分。



\### 4.3 全局状态与数据模型



基于 Java 实体类统一封装全局状态，贯穿多智能体流程与微服务节点。核心数据包括：



\- 项目来源信息

\- 仓库基础信息

\- 项目文件树

\- 全量源码内容

\- 架构解析结果

\- Bug 风险列表

\- 业务规则数据

\- 代码 Diff 变更数据

\- 生成文档内容

\- 用户自定义配置

\- 项目运行判定结果

\- 异常错误信息

\- 评测指标数据



\### 4.4 多智能体分工



\- 仓库资源解析 Agent：对接 JGit 与 MinIO，完成仓库拉取、解压、过滤、文件树构建

\- 静态代码解析 Agent：基于 Tree-Sitter 提取类、方法、依赖、调用关系

\- 架构逆向 Agent：分析模块结构，生成拓扑图与架构说明

\- 代码审计 Agent：扫描缺陷、依赖冲突、架构隐患，风险分级

\- 业务规则逆向 Agent：还原流程与约束，执行一致性校验

\- 文档注释生成 Agent：按配置补全注释、生成文档

\- 代码智能修复 Agent：生成修复方案与 Diff

\- HITL 人工审核 Agent：支持确认、修改、驳回、多轮迭代

\- 运行判定 Agent：识别中间件依赖，区分沙箱运行与本地导出

\- 评测迭代 Agent：完成指标评测、错误溯源、迭代优化



\### 4.5 核心流转逻辑



项目多源导入 → 仓库资源解析 → 静态代码解析 → 架构逆向分析 → 代码缺陷审计 → 业务规则逆向 → 可选文档注释生成 → 代码智能修复 → HITL 人工审核循环 → 项目运行能力判定 → 沙箱运行/打包导出 → 全流程量化评测 → 结束。



支持异步联动、分支路由、异常重试、循环迭代。

\## 5. 核心创新点



1\. \*\*Java 微服务工程化架构\*\*

&#x20;  基于 Spring Cloud Alibaba 搭建可落地、可扩展的平台，各服务解耦，支持后续迭代与并发。



2\. \*\*静态语法解析 + LLM 语义混合架构\*\*

&#x20;  结合 Tree-Sitter 结构化解析与 LLM 语义推理，降低大模型幻觉，提高代码分析准确度。



3\. \*\*多智能体协同工作流\*\*

&#x20;  通过子图封装、分支路由、循环迭代、人工介入，形成“分析—修复—校验—迭代”闭环。



4\. \*\*量化评测体系\*\*

&#x20;  建立测试数据集与指标，支持错误溯源和自动化迭代，弥补多数 AI 项目缺少评估的短板。



5\. \*\*双出口交付机制\*\*

&#x20;  自动判别项目复杂度，轻量项目在线沙箱运行，重型项目本地导出。



6\. \*\*Java 为主的技术栈\*\*

&#x20;  Java 微服务保证工程化能力；智能体服务可独立部署，避免跨语言兼容问题。

\## 6. 项目难点与解决方案



\### 6.1 大项目文件量大、上下文超限、解析效率低



方案：微服务分片解析 + RabbitMQ 异步任务 + Redis 缓存，分模块、分批次解析，避免重复解析。



\### 6.2 纯 LLM 分析存在幻觉，缺陷易误判、漏判



方案：静态规则校验 + Tree-Sitter 结构化解析 + LLM 语义推理三层校验。



\### 6.3 跨模块业务逻辑复杂，规则识别易冲突



方案：增加跨模块一致性循环校验节点，初步解析后比对多模块规则，触发二次回溯解析，并支持人工确认。



\### 6.4 智能体输出效果无法量化



方案：建立标准化测试数据集，量化 Bug 检出率、架构识别准确率等指标，溯源出错节点，针对性优化 Prompt 与规则。



\### 6.5 项目环境复杂，线上运行存在安全与兼容风险



方案：智能环境判定，拆分在线沙箱与本地导出双路径；沙箱隔离运行，默认不执行危险代码。



\### 6.6 多微服务联动复杂，本地调试与线上部署适配难



方案：先本地单服务调试，再集群联调，最后线上部署；本地稳定后再容器化上线。

\## 8. 阶段性目标效果



用户通过仓库地址、压缩包或源码文件导入项目后，系统自动完成：

系统基于 Java 微服务工程化搭建，兼顾本地开发便捷性与线上部署可用性，后续根据实际反馈持续优化。

## 9. 技术验证结论（2026-09-15 补充，取代前文所有「待验证」标注）

> 完整依据见 `docs/tech-spike.md`。本节所有版本号均经 Maven Central 仓库元数据与 POM 父链实测确认。

| 验证项 | 结论 | 关键证据 |
|---|---|---|
| Spring Cloud Alibaba ↔ Spring Boot 3.x | **确认可用**。推荐 Boot 3.5.15 + Spring Cloud 2025.0.3 + SCA 2025.0.0.0 | SCA 2025.0.0.0 的 parent 为 `spring-cloud-dependencies-parent:4.3.0` → SC 2025.0.x → `spring-cloud-build:4.3.4` 声明 `spring-boot.version=3.5.15` |
| LangGraph Java SDK | **存在且推荐采用**。`org.bsc.langgraph4j:langgraph4j-core`，LTS 线 `1.8.27`，要求 Java 17+，内置 LangChain4j / Spring AI 适配 | Maven Central 实测最新 `1.9.0-beta7`；README 声明 1.8.x 为 LTS |
| LangHarness Java SDK | **不存在**。检索无任何同名 Java 制品，仅有「Harness Engineering」概念 | **决策：自研轻量评测模块**（阶段 9） |
| Tree-Sitter Java 绑定 | **确认可用，部署复杂度最低**。`io.github.bonede:tree-sitter:0.26.6` + `tree-sitter-java:0.23.5` | 原生库随 jar 内置（Zig 交叉编译），**明确支持 x86_64-windows**，无需本机 C 工具链 |
| 降级方案推荐 | **首选全 Java（LangGraph4j）**；失败则降级方案 A（Java 业务 + Python LangGraph 服务） | 方案 B/C 可作为二级备选，详见 tech-spike 第 7 节 |

### 9.1 由本次验证导致的选型修正

1. 前文「LangGraph4j（待验证）」→ **确认可用，定为智能体编排首选**。
2. 前文「LangHarness 或自研评测模块（待验证）」→ **LangHarness 确认不存在，定为自研评测模块**。
3. 前文「Tree-Sitter 优先 Java 绑定；若部署复杂可拆独立解析服务」→ **Java 绑定部署简单，无需拆独立解析服务**。
4. 前文「Spring Cloud Alibaba，具体版本以官方兼容矩阵为准」→ **锁定 2025.0.0.0**。
5. 项目要求 Spring Boot 3.x，故排除 SCA 2025.1.0.0（其父链指向 Spring Boot 4.0.8）。
